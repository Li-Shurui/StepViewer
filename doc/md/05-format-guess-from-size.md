# 按文件大小反推格式

打开未知来源的裸数据文件时，常见的困惑是"知道分辨率，不知道像素格式"。
本功能把这个判断自动化：格式下拉框中，**与文件大小匹配的格式以粗体显示**，
鼠标悬停还会显示每帧字节数和总帧数。

## 匹配规则

对下拉框中的每个格式，以当前宽度/高度构造**紧凑布局**
（`defaultStride(width)`、`scanline = height`）：

```
frameSize = decoder->expectedByteSize(tightLayout)
匹配条件: fileSize >= frameSize 且 fileSize % frameSize == 0
```

- 多帧文件天然支持：3 帧 NV12 文件同样匹配 NV12（提示"共 3 帧"）；
- 不满足布局约束的格式直接排除（如奇数宽度时所有 4:2:0/4:2:2 格式
  在 `validateLayout` 阶段就失败）；
- 带 stride/scanline padding 的文件不会匹配——这是有意为之的
  启发式：文件名带标签时本来就不需要猜。

## 触发时机

`updateFormatMatches()` 在以下时机重新计算：

- `init()` 完成时；
- 宽度 / 高度数字框的值提交变化时（`keyboardTracking` 关闭，
  不会逐键抖动）。

## 实现要点

- 纯 UI 层功能，不改动解码器；匹配项用 `Qt::FontRole` 加粗，
  提示文字放在 `Qt::ToolTipRole`；
- 只读文件元数据（`QFileInfo::size()`），不读文件内容；
- 不会自动切换当前选择——匹配只是建议，决定权在用户。

## 使用示例

一个 3 113 600 字节的文件，设置 1920x1080 后：

- **NV12 / NV21 / I420 / YV12**（1920×1080×1.5 = 3 110 400 … 不匹配）
  —— 等等，3 113 600 = 1920×1080×1.5 + 3200？不匹配任何格式；
- 若文件为 6 220 800 字节，则 4:2:0 四格式显示"每帧 3 110 400 字节，
  共 2 帧"，**YUY2/UYVY/I422…**（4 147 200/帧）不匹配。

粗体集合立刻把候选范围从 24 种格式收敛到个位数。
